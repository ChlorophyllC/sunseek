# 晴游 SUNSEEK：新对话交接

更新于 2026-11-14。请先读本文，再看根目录 `README.md`、`docs/weather-data.md` 和 `docs/travel-data.md`。本文区分已经完成的功能与尚未实施的计划，不要把接口选型或配图建议当作已接通的功能。

## 1. 项目目的与用户偏好

这是一个以天气选择旅行目的地的网站：先选出行日期和偏好（晴天、降雪、细雨、清凉），看全国天气地图，再比较推荐目的地。希望有安全边界，避免推荐极端天气；去过的地方默认从优先推荐中收起，足迹可折叠查看。

用户满意初版视觉，希望逐版打磨。继续沿用现有清爽风格，避免无必要的大改版或迁移框架。

已明确的产品方向：

- 天气始终是主线，景点和旅行内容放在天气详情下方，默认折叠，不做以附近景点地图为中心的产品。
- 推荐优先兼顾省会、代表旅行城市和省份多样性，不能因为某省有很多城市就霸占前排。普通城市仍应可查询，不强制给每个县村写介绍或配图。
- 搜索城市、县镇或村落后，先预览天气，再决定是否保存；不能先保存才能看天气。
- 不喜欢维基百科附近检索，也不希望靠距离排序堆出不相关景点。该方案已经撤下。
- 目前先打磨国内体验；中期考虑亚洲，长期支持全球。海外地名、时区和底图尚未开放。
- 用户已授权将项目上传到自己的 GitHub。上传代码不等于发布网站；目前没有要求开通 GitHub Pages 或 Cloudflare 生产部署。

## 3. 已实现功能

### 地点与地图

- 485 个本地地点，含 48 个精选目的地；其余主要来自 DataV 的城市、自治州及部分区县中心点。不能宣称已覆盖所有县村。
- 全国、省份、七个大区、城市附近地图；搜索地区和地点；港澳有更细轮廓，省界悬停在独立上层，线宽已调细。
- 地图是天气采样点示意，不是道路地图，也不代表全省每处天气。标签会避让，因此不是每个地点同时显示标签。
- 默认推荐按省份分轮展示；完整推荐列表与右侧排序同步，不丢弃同省候选。
- 自定义地点、在线地名查询、地图选点、出发地和近似直线距离、最多 3 地对比、足迹与笔记。

### v0.5.2 地图交互

- “全国 → 大区 → 省份 → 城市附近”各上级可点击返回，省份归属大区由地点配置推导。例如内蒙古始终可以返回华北。
- 省份/城市附近地图不再禁用周边省界点击，悬停高亮与 Enter/Space 也可切换；跨大区切换后更新层级，不沿用旧大区。
- 当前地区标签优先布局，可见周边城市淡化标记。展示周边地点只作地图计算，不加入请求队列或推荐。点击周边城市才切换到其附近地图并仅请求该地点；点击周边省份才按原规则加载该省。
- 全国、华南、广东和港澳视图提供独立香港/澳门快捷按钮；港澳原本就在华南，快捷入口不改变其地理位置。
- `assets/subdivisions/` 按省加载下一级区划细线，仅装饰且不接收点击。使用同一批缓存 DataV 源，33 个范围有边界，台湾为空。脚本 `scripts/build_subdivisions.py` 不联网，重建输入同地点索引。
- 城市标签先按当前推荐排序而非地点库顺序摆放，默认保持完整天气标记的清爽布局；“显示更多地点圆点”默认关闭，开启后补充名称放不下的地点。开关只影响地图、不请求天气，同一页面内切换地区保留，刷新恢复关闭。`tests/map_detail.py` 验证青岛第四名在四种宽度仍有名称、开启圆点后山东 16 个视野内地点不丢失，以及区划加载/复用/失败/迟到响应隔离。详见 [地图绘制说明](map-display.md)。
- 单日地图日期、天气偏好与行程日期在地区切换时保留。手机导航换行，地图重绘保留导航按钮焦点。
- `tests/map_navigation.py` 覆盖层级返回、周边实际指针点击、键盘和悬停、请求隔离、日期与焦点、四种宽度；已有地点、规划、网络、主流程、旅行预览与配图回归均通过。

### 天气与稳定性

- Open-Meteo Forecast API：首次串行请求 48 个精选地点，每批最多 16 个；其余按省份或单地点查询。
- 请求未来 16 天日级和小时级预报，当前统一 `Asia/Shanghai` 时区。
- 推荐只统计所选活动窗口内的白昼小时，今天已过去的小时不算。保留完整性检查、天气匹配解释、夜间危险天气排除。
- 单次请求超时 22 秒。网络错误、超时、5xx、响应地点数量不符最多自动重试一次；4xx 包括 429 不自动重试。单批超时不再取消后续全部批次。
- 省份显示完整/查询中/获取失败/日期或小时不全的数量，并提供“重试缺失预报”。
- 1 小时内复用真实缓存；更新失败时最多保留 6 小时内缓存。过期或缺失数据不补零，不用示例天气顶替真实预报。
- 2026-11-14 的一次真实浏览器查询：广西 14 点、吉林 10 点都返回 16 天数据，字段无空值。没有复现用户当时的“—”；只能确认并修复批次超时缺陷，不能认定用户原问题必然由它造成。

2026-11-14 17:47 的 v0.5.1 真实浏览器抽查：首屏与广西/吉林累计 68 个地点，均返回 16 天、384 小时、请求字段无空值；缓存重载与明确的断网注入回退正常。仅代表当前开发机，不是国内多网络验收。详情见 [天气检查报告](weather-check-2026-11-14.md)。

### v0.5.0 新功能

- 地图下方日期条：在整段行程与某一天间切换。单日地图单独计算着色、标记、提示和数据完整性；右侧推荐与目的地对比仍按完整行程。
- 地图日期支持横向滚动、键盘方向键、Home / End。切换地区/偏好保留预览日；行程改变后预览日不在范围内则回到整段行程。
- 城市详情增加默认折叠的出发日期建议，位于逐小时/全天预报之后、旅行灵感之前。
- 从明天至预报末日比较连续 N 天，沿用天气偏好、活动时段、温度和每日匹配条件。这里比较单个已选地点的天气，不按距离或是否去过排除。
- 先按分数、合拍小时、较早出发排序，取最佳一段后再取不重叠候选，最多 3 段。完整性不足、过期或危险天气均不生成完整候选。
- “用这段日期”更新整站行程；未保存地点继续保持临时预览，不写入地点库、足迹或真实缓存。比较日期不额外请求天气接口。

- 普通/自定义地点仍无图回退；图片加载失败也回退到地点示意，详情同步说明。资源均为相对路径。

## 7. 本地运行与测试

在项目根目录：

```sh
python3 -m http.server 4173
```

浏览器访问 `http://localhost:4173`。若端口已有本项目服务，直接复用，不要反复启动。不是 Node 项目，没有 `npm test` 或构建步骤。

开发测试依赖 Python Playwright 与 Chromium，现有开发机已安装。新环境按 README 安装；测试用例依赖支持 `page.clock` 的 Playwright。六组原有回归、配图专项与两组地图专项命令（配图专项另需 Pillow）：

```sh
python3 tests/engine.py
python3 tests/smoke.py
python3 tests/places.py
python3 tests/attractions.py
python3 tests/weather_network.py
python3 tests/planning.py
python3 tests/city_images.py
python3 tests/map_navigation.py
python3 tests/map_detail.py
```

- `engine.py`：28 项计算边界检查，含累计区间、夜间危险天气、缓存和连续出发日期。
- `smoke.py`：主流程、偏好、对比、足迹、缓存、失败/演示、5 种宽度。
- `places.py`：地区/地点搜索、地图、地域排序、自定义地点、兼容与转义。
- `attractions.py`：天气优先、旧收藏、临时预览/保存/关闭隔离，零 Wikipedia 请求。
- `weather_network.py`：独立超时、广西缺失恢复、吉林限流、手机重试。
- `planning.py`：单日地图与整段推荐隔离、日期建议/采用、未保存地点、过期/演示、4 种宽度。
- `map_navigation.py`：层级返回、周边实际点击、键盘与焦点、按需查询隔离、四种宽度。
- `map_detail.py`：港澳快捷入口、下级区划加载/复用/异步隔离/失败回退、青岛第四名标注、圆点默认关闭与开关。

## 8. 需要保持的边界

- `weather.js` 中降水、降雪和最大阵风采用前一小时累计口径：例如 09:00–10:00 槽使用 10:00 的累计值，瞬时条件用 09:00。不要不经验证改变。
- 不把空值当作 0，不用演示或其他供应商的零散字段拼成“完整真实预报”。
- 不破坏 `sunseek-footprints-v1`、`sunseek-preferences-v2`、`sunseek-places-v3`、`sunseek-weather-v3`、`sunseek-wishlist-v1` 的既有数据。用户数据只在浏览器，不随 Git 上传。
- 临时预览必须不进入持久天气缓存、地点库、推荐和足迹；关闭后迟到的响应不能复活已关闭预览。
- 单日地图预览与整段行程推荐保持区分；采用日期建议才更新主行程。
- 地域多样性要覆盖完整推荐列表，不能只对首页前三名生效。
- 不重新引入附近百科距离列表或让旅游内容盖过天气。
