# 地名索引的体积、性能与压缩加载

2026-11-15，v0.8.2。本轮保留全部 25,569 条地名、628 组归属上下文及原匹配规则，不删除别名或县镇记录。

## 大文件实际影响什么

`assets/search-places.json` 原始 UTF-8 体积 2,944,072 bytes，约 2.94 MB。首屏和空搜索不请求它，首次输入至少两个字才加载；当前页面只加载一次，输入不会重复下载。它是静态文件，不需要服务器解析或搜索，不会触发 25,569 个天气查询。服务器主要承担文件存储与下载流量；浏览器承担解码、准备检索字段、匹配排序及内存开销。

较慢网络的首次搜索需要等待下载，较慢设备还可能在准备检索字段时短暂停顿。跨页面刷新能否免下载取决于浏览器 HTTP 缓存，不等于永久缓存。原文件已通过共享上下文和数组行减少重复文本，不能仅按源文件长度判断实际运行内存。

## 已完成优化

- 新增确定性 gzip 产物 `assets/search-places.json.gz`：889,886 bytes，减少 **69.8%** 的索引内容传输。
- 支持 `DecompressionStream` 的浏览器先取 gzip，在本机解压；原始 JSON 继续保留供维护与兼容。
- 浏览器不支持解压、压缩文件缺失或损坏时回到原 JSON。兼容托管层已通过 `Content-Encoding` 自动解压的响应，避免重复解压。
- 首屏/一字输入不加载、会话内复用、当地名索引仍在加载时不提前在线搜索等行为保留。源索引和搜索结果不变。
- 一轮检索只预处理查询词一次，避免对 25,569 条记录重复做相同的标准化、后缀和分词处理。

生成与核对：

```sh
python3 scripts/compress_search_index.py
python3 scripts/compress_search_index.py --check
```

原 `build_search_places.py` 在生成源 JSON 后也自动更新 gzip。gzip 使用空文件名和固定 mtime，重复生成逐字节一致。无需新增运行依赖或构建框架。

本地/发布包保留原文件和 gzip，因此运行文件总存储增加约 0.89 MB；正常支持浏览器只下载压缩文件。压缩文件传输到浏览器后仍会展开为原数据，不能将节省下载量解释成同比减少内存。

## 本机实测及限制

Chromium、390px 视口、本机静态服务器、天气与在线搜索使用模拟响应。以实际索引对晋城、宁波象山、花鸟岛、安徽黄山、北京、上海六个查询排序：

| 测量 | 改动前 | 改动后 |
| --- | --- | --- |
| 首屏 / 空搜索索引请求 | 0 / 0 | 0 / 0 |
| 索引内容传输 | 2,944,072 bytes | 889,886 bytes |
| 本机单轮排序 | 约 20–25 ms | 约 9–15 ms |
| CPU 降速 4 倍时单轮排序 | 约 86–101 ms | 约 37–58 ms |

JSON 解析本机约 4 ms；准备全部检索字段约 0.2 秒，CPU 降速 4 倍时约 0.8 秒，此项尚未分片或迁入 Worker。降速模拟不等于真实手机测量。

另一个独立本地页面，主动 GC 后的 JS 堆从加载前约 4.79 MiB 增至搜索就绪后的 41.70 MiB，增量约 36.90 MiB，包含准备后的索引和搜索界面。不是 2.94 MB 文件本身占用了所有这些内存，也不是手机内存保证值。本轮优先减少网络传输及重复计算；后续如真机输入仍卡顿，再评估后台线程和索引结构，不贸然按省分片削弱全国搜索。

新增 `tests/search_asset.py` 验证字节还原、真实压缩传输、按需加载、会话复用、缺失/损坏/不支持/已解码回退，以及不增查天气。原搜索、节流、地点与手机测试继续通过。

## 线上发布

已通过原发布工具更新 `sunseek-004` / buildId `2612783856`，原域名和 `/sunseek` 挂载不变，运行文件 154 个。真实站点的 HTML、主脚本、搜索脚本和 gzip 资源摘要与本地一致。390px 浏览器首次搜索只请求一个 gzip，实际内容传输 889,886 bytes，本次约 355.5 ms；继续检索不新增索引请求。晋城、宁波象山、花鸟岛、安徽黄山搜索正常，无页面 JS 错误或横向溢出。
