# 地图层级、区划与城市标记

更新于 2026-11-14。本轮地图交互改动归档为 v0.5.2；网站继续本地运行，尚未部署。

## 港澳与地区切换

香港和澳门已经属于“华南”，范围配置在 `destinations.js`。真实地理比例下，两地轮廓在全国或华南视图中很小；当前在全国、华南、广东和港澳视图增加独立“香港 / 澳门”快捷按钮。按钮直接展开对应地区的地图与按需天气，不改变主地图的比例或挪动行政位置；只显示按钮不会额外请求天气。

地图上方保留“全国 → 大区 → 省份 → 城市附近”的层级返回。可见周边省界与城市继续可以切换，省份归属大区根据配置重新推导，切换不会重置所选地图预览日期。

## 省内下一级边界

在省份及城市附近视图显示淡色细线，省份通常是市/州边界，直辖市和港澳采用现有源提供的区县/堂区等边界。线条只作区划示意，不支持点击进入下一级，也不单独给各区划着天气颜色。省份底色仍是已覆盖天气采样点的汇总。

原始资料与现有 `assets/places.js` 相同，为此前下载的阿里云 DataV `{省级代码}_full.json`。使用 `scripts/build_subdivisions.py` 简化并保留本地静态轮廓：

```sh
python3 scripts/build_subdivisions.py /tmp
```

输入是缓存目录中的 `sunseek-area-{省级代码}.json`。脚本不联网，不重新抓取，也不生成虚构边界。34 个省级范围文件合计 2,612,824 bytes（约 2.6 MB），其中 33 份有可用的下级边界；台湾缓存源不可用，保留明确空记录。不能据此宣称覆盖最新全部行政区划。

`assets/subdivisions/sources.json` 列出逐省原始来源、子区划数量与文件体积。浏览器首次展开省份才读取该省文件，同一会话复用；全国与大区视图不加载全部边界。装饰线裁剪在当前省级轮廓内，澳门沿用已有 Natural Earth 陆地外形裁剪，避免将源中的水域范围当作陆地。装饰层不接收指针事件、不进入键盘顺序；文件加载失败只省略装饰，迟到的旧省份响应不能覆盖当前地图。

## 为什么有些城市原来没有名字

之前的全国视图以精选省会、代表旅行城市为主。进入省份后，该省本地已收录的地点都会成为标记候选；这不等于覆盖全省所有县村。城市名称还要经过视野检查与碰撞避让，因此候选不一定都出现在图上。

旧布局只给当前首选地点优先位置，其他城市沿地点库顺序尝试左右摆放。摆不下时会连同整个标记一起省略。地图标签不是天气榜单的前 N 名，因此“推荐第四但地图没有”完全可能是布局省略，不能推断为未收录或天气被排除。本次没有保存用户当时的浏览器状态，不能还原那一次具体与谁发生重叠。

本轮规则调整为：

1. 当前定位/首选地点优先，再优先当前地区的地点。
2. 符合推荐的地点按当前推荐排序分配完整名称；单日预览使用该日评估，主推荐仍按完整行程。其余地点继续显示，出发地、省会和精选身份作为后续优先项。
3. 名称尝试左右和上下避让，适当使用引导线。默认不显示名称放不下的地点，保持完整天气标记的视觉。可在地图下方勾选“显示更多地点圆点”，以圆点补充这些位置，仍有名称、键盘入口、悬停提示与点击详情。开关只影响展示，不改变现有完整标记的位置、不请求天气；同一页面切换地区保留，刷新恢复默认关闭。
4. 周边地点次于当前地区，采用淡化标记；尚未查询天气时显示不可用状态，不把空值当作晴天。仅展示周边不会添加天气请求或改变推荐候选。

地图标记仍是坐标采样点，不是景区导航。视野以外的地点需要调整地区或搜索；近邻地点过密时也可以用搜索精确打开。

## 验收

`tests/map_detail.py` 使用确定性天气，让济南、烟台、潍坊排在青岛之前，并断言青岛为第四名。在 1440 / 768 / 390 / 360px 下，青岛仍有名称，默认关闭圆点时保留高匹配城市名称；开启后山东视野内的 16 个地点都保留标记。另验证开关不移动完整标记、不增加天气请求、切换地区保留但刷新恢复关闭，以及拥挤圆点可点击打开详情。

同时检查港澳快捷按钮、手机点击区域、返回华南、单日预览保留、省级轮廓裁剪、区划按需加载/复用、装饰不拦截点击、旧请求迟到隔离、缺失源和资源加载失败回退。上一轮层级导航由 `tests/map_navigation.py` 继续验证。
