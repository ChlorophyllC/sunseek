## 主要阻塞

| 项目 | 当前网页 | 小工具要求 / 结论 |
| --- | --- | --- |
| 实时天气 | `app.js:1042` 直接请求 Open-Meteo；实验共享服务也需请求外部函数 | 网页外部网络请求被禁；公开能力中没有通用 HTTP 代理或天气接口。核心功能无法等价迁移 |
| 在线地名搜索 | `app.js:1155` 请求在线地理编码 | 同样无法使用；只能缩减为包内静态地点 |
| 原样压缩体积 | 11,122,684 bytes，约 **10.61 MiB** | 超过 10 MiB 硬上限，官方体积审计失败 |
| 文件类型 | 包含 `assets/search-places.json.gz` | `.gz` 不在允许类型中，不能原样上传或仅改后缀隐藏 |
| JS 兼容 | 可选链、空值逻辑赋值、可选 catch 参数、Unicode 属性正则等；还使用 `flatMap`、`AbortController` | 不符合直接交付 ES2017 / Chrome 61 的基线，需要专门改写与能力回退 |
| CSS 兼容 | Flex gap、`aspect-ratio`、`:focus-visible` 等 | 需要旧内核的基础布局与焦点回退，不能因现代浏览器正常就认定兼容 |
| 备份与外链 | JSON 文件导入、浏览器下载、GitHub / 来源外链 | 文件选择只开放图片和视频，网页下载与站外跳转不可照搬 |
| 本机记录 | 当前以浏览器 localStorage 保存 | 应优先适配平台 Storage，并处理版本、失败和迁移；天气缓存上限 160 万字符，也不能直接塞入平台单 key 1 MiB 限额 |

包体和兼容性可以通过适配解决，但不解除实时天气的数据来源限制。把天气改成固定示例，或让 AI 生成所谓“预报”，都不能算作晴游原功能的迁移。

## 在线能力与随包基线的差异

已向用户播报新增公开文档能力，均须遵守对应版本及授权条件：

- AI 文本生成：`AI.createModel(...).generateText(...)`，内测加白。
- 窗口信息 `getWindowInfo` 与单次定位 `getLocation`：9.49+。
- `vibrateShort` / `vibrateLong`，以及 `startGyroscope` / `stopGyroscope` / `onGyroscopeChange` / `offGyroscopeChange`：9.50+。
- 关注作者 `followAuthor` / `getFollowStatus`：9.51+。
- 分享 `share`：9.53+，仅全屏容器。
- `rewardAuthor` / `setCloseRetentionEnabled`：9.53.3+，赞赏相关内测能力。
- 支持受约束的包内 classic Dedicated Worker（9.53+）和平台管理的静态资源优化（最低 9.53.3）；都不开放页面外部联网。
- 既有发布接口的实况照片字段从基线的 `live_photo_sources` 更新为在线文档的 `live_photo_resources`。本轮不调用发布接口。

这些能力没有提供晴游所需的实时天气数据通道，因此本轮不接入，也没有尝试借用私有 bridge 或绕过容器限制。
