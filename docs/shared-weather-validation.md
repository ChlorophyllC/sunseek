# v0.8.0 共享天气缓存真实验收

日期：2026-11-15（Asia/Shanghai）。后端部署在原上海区体验环境，静态测试网页本轮没有发布。测试不是演示天气；常规确定性测试与真实云端检查分别记录。

## 结论

先完成 48 个精选地点两轮真实调用，再将同一个函数扩展至全部 506 个采样点。506 点均已写入共享 PostgreSQL，第二轮逐批读回时每个点的源时间戳完全保持。两个独立浏览器实际访问 HTTPS 服务，各接收 48 点、仅 3 个共享请求，浏览器直连天气接口均为 0；刷新后使用本机缓存，无额外共享请求。

## 时延与失败恢复

48 点复验第二轮：三批均无 `weather-upstream` 事件，函数内耗时 6 / 5 / 6ms；这不包含浏览器网络往返。

全库验收开始时 48 点已经新鲜，其余按需填充。首轮完成共 461.6 秒，34 次请求，其中 3 批发生部分/全部失败，总计 32 个地点结果需要重新尝试；每次均遵守 60 秒冷却，仅补失败或后续缺失点，不重取成功点。首轮请求时延中位数 7,084ms，最大 22,554ms。因此不能宣称全库冷启动很快，也不能只用热缓存数值估算真实首次等待。

全库第二轮 32 批 HTTPS 读取共约 8.6 秒，每批实测 150–612ms，506 点全部保留首轮真实 `fetchedAt`。没有定时全库刷新任务；此次完整填充是用户明确要求的单次验收。

原始天气此时最远一天存在空值，48 个精选经过原引擎校验后只有 15 个有效日；完整时间轴不是完整有效天气。保留 null 和缺失说明，不补零、示例或旧日数据。前端持久保存原请求基准日，真实浏览器刷新时不会仅因末日空值而重复查询。

## 权限、并发与异常检查

真实 SQL 在事务中运行并回滚，覆盖：

- 匿名/登录浏览器角色不能读写私有缓存表，不能执行私有 SQL 函数。
- 两个 owner 竞争相同地点，只有第一个拿到租约；租约到期后新 owner 可接管，旧 owner 不能覆盖。
- 读取不延长获取时间；profile 变更不能复用旧预报。
- 429 保留旧预报并设置共享暂停；滚动分钟预算耗尽后不能继续取得新租约。

真实独立 Function URL 拒绝：未知地点（400）、`force=true` 强刷参数（400）、非允许 Origin（403）及 POST（405）。CORS 仅列出晴游站点和本地 4173 的精确来源。未设置通配网关或全环境公开策略。

平台拒绝在内部默认域名上手工创建网关路由；通配域名方案被自动审批拒绝。最终使用只绑定 `sunseek-weather-cache` 的 Function URL，未重试或间接创建被拒绝的通配路由。

## 常规回归

原 16 组 Python 回归全部通过；新增浏览器共享缓存专项，以及 Node 核心和 HTTP 事件专项，共 19 组。原有测试显式选择确定性直连夹具，真实后端检查必须主动运行，不能混入普通回归。

新增覆盖独立浏览器、全国/省份/全库隔离、时间戳、并发/pending、手动重试、429、服务故障停止队列、不回退直连、末日缺失后的本地复用，以及共享脚本加载失败时不引发浏览器集体回源。

可复现命令见 [共享服务实现与运维](shared-weather-cache.md)。本机原始摘要位于 `/tmp/sunseek-shared-featured-live.json`、`/tmp/sunseek-shared-all-live.json`、`/tmp/sunseek-shared-db-summary.json`；不把完整天气响应、凭据或个人浏览器记录提交仓库。

## 发布与计量边界

本轮只部署新的天气后端，未更新 `sunseek` 静态应用、套餐、自定义域名或超额计费开关。前端代码仍需按用户安排同步静态测试站后，线上访客才会开始使用此服务。

用量接口返回本周期 3000 点、已扣 25.99 点，但本轮函数/SQL 明细尚有统计延迟。不要把零值当作零成本；试用后应核对函数出流量、计算和 PostgreSQL 的真实计量。Function URL 缓存头已返回，但未验证 CDN 命中，不把它宣传为已经经过 CDN 复用。
