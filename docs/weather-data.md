# 天气数据：缺失排查与备用接口

核对日期：2026-11-14。本版仍使用 Open-Meteo，没有接通新的付费接口。

v0.5.1 的真实浏览器抽查记录见 [2026-11-14 天气检查](weather-check-2026-11-14.md)：开发机首屏及广西、吉林累计 68 个地点返回完整 16 天数据，缓存复用与故障注入回退正常。结果仅代表该开发环境和时间点。

v0.5.0 的逐日地图与出发日期建议直接复用已获取的预报，不新增接口调用。单日预览只改变地图，主推荐仍按整段行程；日期建议从明天起比较同一地点的连续完整行程，继续排除缺失、过期数据和恶劣天气，演示结果明确标注。

## 这次“展开省份后显示 —”的排查

“—”目前表示所选时段没有完整的评分数据，不一定表示该城市没有任何天气数据。连接失败、请求超时、所选日期缺失，或者某个白昼小时缺少体感、云量、降雪量等必要字段，都会造成不完整。完整性要求是为了避免把缺失值当作零降水或晴天。

本次在实际浏览器中查询初始 48 个精选地点，再依次展开广西、吉林：广西共 14 个地点（另增查 12 个），吉林共 10 个地点（另增查 8 个）；相关请求均返回 HTTP 200，逐日数据均有 16 个日期，请求的日级和小时字段没有空值。这次没有复现用户当时的缺失，不能据此推断此前没有故障，也不能判定是地域覆盖不足。

代码中确认存在一个独立缺陷：旧逻辑在某批请求超时后，取消了整个刷新共用的 AbortController，后续批次也会立即失败。现在每次请求使用独立超时控制，父控制器仅用于明确取消整次查询。

本版处理方式：

- 每批仍最多 16 个地点，串行请求；单次超时 22 秒。
- 网络错误、超时、HTTP 5xx、响应地点数量不符，最多自动重试一次；HTTP 4xx（包括 429 限流）不自动重试。失败后继续处理后续批次。
- 省份地图显示完整、查询中、获取失败、日期或小时不全的数量。悬停和城市详情解释失败原因。
- 增加“重试缺失预报”，只重新请求当前省份不完整的地点。全部完整后隐藏按钮，查询过程中禁用。
- 失败时沿用原有的有效缓存和到期规则；不以演示数据补齐真实预报，也不降低推荐所需的完整性要求。

新增 `tests/weather_network.py`，用确定性响应验证超时隔离、广西失败/缺字段/恢复、吉林 429 限流与手动重试，以及手机按钮布局。已有主流程、地图地点、自选地点预览测试也继续运行。

## 可选数据源与用途

### 彩云天气：优先做接入验证的候选

已读取官方[逐小时文档](https://docs.caiyunapp.com/weather-api/v2/v2.6/3-hourly.html)、[逐日文档](https://docs.caiyunapp.com/weather-api/v2/v2.6/4-daily.html)和[开发入口](https://docs.caiyunapp.com/weather-api/dev.html)。

- 按经纬度查询；逐小时字段包括天气现象、气温、体感、风、降水、云量等。比只有早晚天气描述的接口更接近本产品需求。
- 文档列出 `hourlysteps` 为 1–360，默认 48；实际上限由套餐决定。逐日通常为 1–15 天，默认 5；`dailysteps=16` 需同时回退一天，不能理解成完整的未来 16 天。
- 需申请 API 凭证。预警也有独立权限要求；不承诺默认套餐包含所有时效和功能。本次只核对文档，没有凭证，尚未验证真实返回、国内可达性、准确度或成本。
- 当前常规逐小时字段表未列出与本项目直接等价的独立降雪深度累计量、最大阵风字段。天气代码中的“雪”不能当作厘米降雪量，普通风速也不能当作阵风，因此还不能直接替换当前四种偏好的全部评分与恶劣天气检查。
- 文档说明中国大陆请求使用 GCJ-02，其他地区使用 WGS84；项目地点目前存储为 WGS84。接入时要验证坐标转换，且彩云请求路径为“经度,纬度”，不能直接复制当前请求的参数顺序。

建议先选广西、吉林和几个不同气候区的城市，用真实账号做同一日期、同一地点的对照；确认必要字段、可用时长、耗时和配额，再决定作为主源还是补充展示源。没有这些验证前，不以“国内接口”推断它一定更完整或准确。

### 高德天气：适合基础天气展示的备用

已核对[天气查询官方文档](https://lbs.amap.com/api/webservice/guide/api/weatherinfo)。需要 Web 服务 API Key，按城市行政编码查询实况或预报；预报主要提供白天/夜间天气、温度、风向和风力。

它适合补充“这个城市近期大致什么天气”，但文档没有本项目计算白昼合拍小时所需的完整小时字段，不能替代逐小时评分。若以后接入，应明确显示“基础天气可用，小时匹配暂不可用”，不能将早晚概况补成 24 个小时。

### 和风天气：保留候选，尚待核实

本次访问官方逐小时文档返回 HTTP 403，未取得可核验的具体内容。暂不据此填写天数、免费额度、降雪量或阵风支持情况，也不把文档访问失败等同于服务不可用。后续取得可访问的官方文档与账号权限后，再加入同一套实测。

## 真正接入第二来源时的边界

1. 先加本地可运行的服务端代理，将凭证放在环境变量中；不写进前端或 Git。不需要为了验证接口立刻上线网站。
2. 按来源分别处理坐标、天气代码、单位、时区、降水累计区间、预报有效范围和缺失字段；不能沿用 Open-Meteo 的字段假设。
3. 每个地点记录来源、获取时间和可用日期。切换整份预报，不把不同来源的降水、风、雪拼进同一个小时制造“完整”结果。
4. 缺少评分必要字段时允许展示已有基础天气，但明确标注不参与完整评分。日期控件和推荐覆盖率须反映实际预报范围。
5. 对限流设置退避和共享缓存，避免每位访客都重复请求全国地点；账号配额、计费和内容展示权限以实际授权为准。

当前建议：先使用本版的请求隔离和缺失重试观察问题；下一步优先验证彩云的实际数据契约，再决定是否切换或增加备用来源。
