# 旅行内容的数据接入方案

更新：2026-11-14。产品主线是天气选目的地，旅行内容仅作为天气详情之后的折叠补充。

## 推荐：城市级高德 POI + 编辑精选

已核对[高德地点搜索 2.0 官方文档](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch)。

- 使用 `https://restapi.amap.com/v5/place/text`，按 `region` 指定城市，配合 `city_limit=true` 约束所属城市。使用景区、博物馆等正式 POI 类别，不使用 `around` 接口或游客可调的半径。
- 官方说明文本检索结果按高德搜索综合权重排列，不是按距离排序，也不是已验证的游客热度榜。
- `show_fields=business` 可申请返回商业信息，文档包含营业时间、电话、评分等字段。评分仅在餐饮、酒店、景点、影院等类别可能返回，可能缺失；不能推出推荐人数。`business.tag` 文档明确目前仅用于美食 POI，不能拿它作为景点评价标签。
- 编辑挑选城市代表地点作为锚点，再用 API 补充位置、营业信息与相关候选。最终只展示约 3 个不同类型的地点，去重同一景区的出入口、售票处、停车场等附属 POI。
- 展示明确的来源与更新时间。评分、开放时间、照片、价格缺失时不生成替代值；评分不改变天气评分。
- 接口要求注册并申请 **Web 服务 API 类型 Key**。调用配额、商业展示和内容使用权限需按账号的实际授权核实，不承诺免费或无限调用。
- Key 应放在未来服务端环境变量中，由固定的查询接口代理，不能写进静态页面或 Git。高德坐标与天气使用的 WGS84 坐标口径不同，接入时需单独处理和验证。

## 旅游平台内容

[携程开放平台](https://open.ctrip.com/)等旅游平台值得进一步洽谈；攻略、评价、榜单与活动比通用地图 POI 更接近旅行决策。但本次没有核实到可直接匿名调用并授权展示这些内容的公开接口，不能把网页评分或榜单当作可自由获取的 API。也不将网页抓取作为替代方案。

## 当前实际实现

尚未提供或配置高德 Key，**本版没有声称接通高德 POI API**。保留静态网站运行方式：

- 撤下维基百科附近检索，不再按距离堆砌附近条目，不再展示 2/5/10 km 选择。
- `assets/travel-highlights.js` 为 12 个城市各整理 3 个代表性旅行灵感，采用原创新简介和近似天气采样坐标；只是编辑选择，不是实时人气榜或官方排名。
- “在高德查看”是跳转到高德地点搜索页面，**不等同于高德数据接入**。
- 未整理的城市显示简短空状态，不用随机附近 POI 填补。
- 旧版百科收藏仍保留原始链接和 CC BY-SA 4.0 标注，不再自动发起百科请求。旧缓存不再使用。
- 查询景点或自选地点时先打开临时天气预览；只有点击“保存这个地点”后才进入个人地点库。临时预览不参与推荐、足迹和持久天气缓存。
