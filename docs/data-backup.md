# 本机旅行记录备份与迁移

更新于 2026-11-14。本功能已归档于 v0.6.0；备份仅存本机，不依赖账号服务。

## 使用

页面底部点击“备份与迁移”。导出生成 JSON 文件，可自行保存或转移到另一浏览器；文件在本机生成，不上传到服务器，也不是账号同步。备份是明文，包含个人地点坐标和足迹笔记。

导入先选择文件，查看备份时间、新增数量、重复与冲突说明，确认“合并导入”后才写入本机。选择文件、预览、切换偏好选项或关闭窗口都不会导入。无新增内容时不重复写入。

## 包含和不包含什么

- 包含当前页面已识别的个人地点、足迹与最多 300 字笔记、想去清单（含旧版百科收藏）、出发地、距离范围、活动时段。
- 导出当前会话的记录，存储受限但仍在页面内的足迹/收藏修改也可备份。未保存的临时预览不在其中。
- 不包含天气缓存、演示天气、API 响应、图片、旧百科资料缓存、主行程日期、天气偏好、对比选择、推荐范围或地图圆点开关；这些不是现有持久旅行记录的一部分。
- 导入不会请求天气。新地点显示暂无预报，打开地点或省份后才沿用原有按需查询规则。真实天气缓存的内容和获取时间不变。

## 合并规则

1. 默认保留本机已有地点、足迹整条记录与收藏；即使本机笔记为空，也不自动拿旧备份覆盖。不会删除本机多出的记录。
2. 同地点去重：同编号且同省、相距不足 10 米视为同地；同省且同 GeoNames 编号，或同省同名且相距不足 1 km，也匹配已有地点。原有名称和坐标保留。也可匹配已有基础/精选地点。
3. 同编号但无法判定同地时，导入地点使用新的个人地点编号；该备份中相关足迹和出发地同时映射到新编号，不覆盖原地点及其天气。
4. 收藏按编号去重。旧百科收藏保留原编号和已有来源展示方式。
5. “同时采用备份中的出发地、距离与活动时段”默认不勾选；只有明确勾选才替换这些偏好。主行程、天气偏好和地图视图保持原状。
6. 重复导入同一文件不会再创建相同地点或足迹。合并后的个人地点、想去清单各不得超过 100 项；超限会拒绝整次导入，不截断记录。

## 文件契约

`backup.js` 是格式校验、归一化、合并和存储写入模块。当前格式为：

```json
{
  "format": "sunseek-backup",
  "version": 1,
  "exportedAt": "2026-11-14T08:00:00.000Z",
  "data": {
    "places": [],
    "footprints": [],
    "wishlist": [],
    "preferences": {"origin": "", "hourStart": 9, "hourEnd": 18, "maxDistance": null}
  }
}
```

- `places`：`id/name/lat/lon/code/timezone/source/geoId`；沿用现有个人地点校验，不携带 `tier`、图片、介绍或天气等运行时字段。
- `footprints`：`placeId/savedAt/note` 数组；需能关联到文件中的个人地点或本版本基础地点库，最多 1,000 条。不能导入悬空足迹。
- `wishlist`：沿用现有收藏的名称、坐标、类型、简介、城市和来源字段；简介最多 400 字、城市名最多 60 字。
- `preferences`：可以为 `null`，否则必须满足出发地引用、06:00–22:00 时段和现有距离选项约束。

文件最大 2 MB。非 JSON、非晴游格式、未知版本、无效引用、重复编号、超长字段或异常坐标等会拒绝整份文件。按白名单重建字段，不把任意对象属性写进应用状态。用户文本按现有转义规则显示。

## 保存与失败处理

只写既有四个键：`sunseek-places-v3`、`sunseek-footprints-v1`、`sunseek-wishlist-v1`、`sunseek-preferences-v2`，不清空 localStorage。

预览时保存本机状态与原始存储快照，检查现有存储能否被完整识别、是否与当前页面一致。提交前再核对当前状态与存储快照；其他页面有修改时拒绝旧预览，需刷新同步或重新选择文件。未识别的原有记录会阻止导入，避免静默丢失。

写入失败时先释放本次分配，再还原已写键；应用内存只在完整保存后才更新。如果浏览器同时阻止还原，会明确提示部分存储未还原，当前页面继续保留导入前记录供导出，并阻止继续导入。此时应先下载原数据，再关闭页面。localStorage 不提供跨键事务，不能声称在浏览器彻底禁止写入时仍可保证持久还原。

文件读取有会话标识，旧文件的迟到读取不能覆盖新预览，关闭窗口后不会复活或导入。失败后可重新选择同一个文件。
