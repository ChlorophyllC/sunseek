# 推荐范围与查询缓存

更新于 2026-11-14。本功能与备份迁移、统一地点搜索一并归档于 v0.6.0。

## 已确认的问题

旧版以“曾经请求过或缓存中已有的地点”作为全国/大区的候选来源。冷启动先查 48 个精选地点，展开省份后更多普通地点进入候选；重新打开又读取这些缓存，导致同样的日期和偏好因浏览历史不同而有不同的推荐数量和省份着色。

本轮以固定天气响应复现：浏览四川前有 27 个合拍结果，返回全国后变为 29 个，四川颜色也改变。这个复现是模拟数据，不是实时天气结论。

## 当前规则

- 页面“推荐范围”默认是“精选目的地”：48 个精选地点，加上已保存的个人地点；有个人地点时选项明确显示“精选与个人地点”。候选身份不由缓存或请求历史决定。
- 个人地点作为用户明确保存的候选，冷启动会一起获取天气；导入备份本身仍不触发请求，后续刷新或打开地点时再查询。
- 全国和七个大区遵循同一选项，再按当前地区过滤。推荐、数量、地图着色、标签优先顺序与汇总更新时间都使用相同候选范围。
- 省内始终使用该省全部已收录地点，因此选项暂时禁用并给出说明。返回全国或大区后沿用本页原先选择。
- 普通地点仍可单独搜索、查天气、对比或作为出发地；仅浏览它不会把它加入默认全国推荐。出发地在视野内可补充标记，但不因此加入推荐或省份天气统计。
- 刷新页面恢复默认精选范围，避免已有大量天气缓存就自动发起全库查询。天气缓存保留逐地点时间与原有 1 小时/6 小时规则。

持久天气缓存限制在约 160 万字符内（UTF-16 文本约 3.2 MB），优先保存精选、个人地点，再保留当前省份/详情和较新查询；更小的浏览器配额下自动缩减为可写入的优先子集。只操作天气缓存键，不改写旅行记录。当前会话仍保留已取得的全部预报，但刷新后未持久保存的地点可能需要重新查询，不能承诺 506 个地点都能落入本机缓存。

## 主动扩展

“推荐范围”下拉框收在原筛选区；进度和缺失重试紧邻结果状态，不再单独占用说明块。

选择“全部收录地点”才会对当前地区的全部已收录地点（含个人地点）查询；全国目前为 506 个本地地点加个人地点，不代表收录所有县村。

每批最多 16 个地点，串行请求，复用仍有效且覆盖当前预报末日的真实缓存。每批完成后更新完整、查询中、获取失败、未查询/不完整数量，可先使用已返回的结果。完整数量不表示符合天气偏好，符合推荐的数量另行计算。

切回精选会取消尚未完成的扩展队列，保留已经取得的真实数据；迟到的响应不能修改当前结果或启动后续批次。切换到另一个地区时，先停止旧扩展，只查询新地区所需地点。未完成的数据不会被补零或用演示天气补齐。

HTTP 429 不自动重试，并停止本轮剩余批次；有效缓存继续可用，稍后可手动“重试缺失预报”。此按钮仅重查当前候选中不完整的地点；普通刷新则更新当前范围及实际打开的详情，不刷新已经关闭的历史地点。网络/超时/5xx 等仍沿用单次自动重试一次的规则。

演示模式下切换范围不发天气请求，示例与真实缓存隔离；退出演示只更新当前范围。

## 验证

`tests/discovery_scope.py` 验证无缓存、浏览省份返回和暖缓存重开时，默认推荐顺序、数量、地图标记与省份颜色相同；验证全库显式查询、每批 16 点、有效缓存复用、切回取消、迟到响应隔离、初次请求未完成时快速切换、大区与省份切换、429 停队列/缺失重试、个人地点冷启动、演示隔离和四种宽度。

这些测试使用固定响应，不消耗真实天气配额，也不能证明真实接口长期可用性或预测准确度。
