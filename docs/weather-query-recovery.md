# v0.8.1 查询恢复与上线记录

2026-11-15。用户反馈接入共享缓存后，本地与线上都更慢，且经常获取失败。

## 原因与修改

v0.8.0 默认把公共地点从浏览器直连改为“浏览器 → 腾讯云函数 → PostgreSQL/天气接口”。本地开发也使用这条云端路径，函数冷启动、数据库调用及上海函数访问上游的不稳定都会影响本地体验。共享服务整体失败还会让前端停止剩余队列，避免集中回源，但也会扩大用户看到的缺失范围。此前全库冷填充出现失败冷却与长等待；仅验证缓存命中后的速度不足以证明首访体验合适。

v0.8.1 默认恢复原先的浏览器直连与逐地点一小时本机缓存，仍按 16 点串行批次、默认精选及按需省份查询。共享后端保留为显式启用的实验路径，普通本地/线上访问均不请求它。没有删除数据库、变配或新增任务，也没有把服务错误自动改成回源风暴；这是统一恢复默认路径。

`app.js` 自己以显式配置判断是否启用共享服务，不再依赖旧客户端模块的默认值。天气客户端和主脚本 URL 增加 `?v=0.8.1`，防止旧缓存重新打开共享路径；共享模块缺失也不妨碍默认直连。此前逐点源时间、覆盖基准日和失败真实缓存规则继续保留，不用演示数据补缺失。

## 后续边界

用户后续已明确：全部地点都不采用定时刷新，精选也不预热。替代共享方案统一按需查询、按地点复用一小时缓存，只有访问遇到缺失/过期数据才更新，并合并同地点的并发请求；无人访问不主动获取。该方案仍待实现，当前线上默认直连路径不变。

先由用户确认本地及手机查询恢复，再设计真正不依赖 PG 活跃窗口的共享缓存。PG 模式云存储的元数据/RLS 仍使用 PG，不能只换 SDK 就声称规避计算计费。后端重新默认接入前，需同时通过冷启动速度、失败恢复和实际账单检查；不要为了测试重复全库回源。
