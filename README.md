# 晴游 SUNSEEK · v0.4.2

按出发地、出行日期与日间天气偏好，寻找中国境内的旅行目的地。保留初版的清爽界面，以天气选择为主，旅行灵感在天气详情后折叠展示；自选地点可以先查天气，再决定是否保存。

当前仅做本地打磨，尚未配置远程仓库、账号服务或线上部署。使用原生 HTML、CSS、JavaScript，无需前端构建工具或 API 密钥。

## 本地运行

```sh
python3 -m http.server 4173
```

浏览器打开 `http://localhost:4173`。刷新即可看到最新修改。推荐通过本地服务器访问，而非直接打开 HTML 文件。

## v0.4.1：天气优先与临时预览

- **先查天气，再保存**：在线搜索结果直接打开天气详情；手动坐标和地图选点确认后也先预览。预览会明确显示“尚未保存”，点击“保存这个地点”才持久化。保存后才可作为个人地点参与对比、出发地与足迹。
- **临时地点不污染数据**：未保存地点不进入推荐、个人地点列表、足迹或持久天气缓存。关闭后清理临时状态；迟到的天气响应不会重新插回已关闭地点。未保存预览不改变原来的地区筛选。
- **旅行内容后置**：逐小时天气、全天预报、天气说明和操作之后才是“旅行灵感”，默认折叠。
- **撤下附近百科检索**：移除半径、兴趣检索和按距离堆砌的结果。当前在 12 个城市提供各 3 个编辑精选，包括市区以外但属于该城市旅行的景点；不是实时热度榜。没有整理的地点不会用随机 POI 补位。
- **保留收藏**：已有想去清单和旧百科收藏继续可用，旧摘要仍附来源链接及许可说明。点击景点“先看天气”同样进入临时预览，不会自动保存目的地。

建议后续以高德城市级 POI 补充精选地点资料。已核对官方文档，但当前没有配置 Web 服务 Key，尚未接通高德数据接口。“在高德查看”仅是外链。接口选择、字段限制、密钥与坐标口径见 [旅行数据方案](docs/travel-data.md)。

## 第三版新增

- **485 个本地地点**：保留 48 个精选目的地，合并阿里云 DataV 的城市、自治州和部分区县中心点。去除同省同名的城市重复记录；城市与包含它的自治州保持不同实体。覆盖基于当前数据源，不宣称收录所有村庄或行政区划；台湾的该版城市级源文件不可用，目前保留精选台北点，其余地点可在线搜索或手动添加。
- **地域多样推荐**：默认在符合天气条件的结果中按省份轮流展示，每轮各省一个，轮内保留天气排序。同省其他结果可折叠展开。“只按天气分数”、其他明确排序及省内浏览不做省份去重。天气分数不变，精选身份只作为分数与合拍小时相同后的排序依据。
- **省份与城市附近地图**：可点击省份轮廓、搜索省份或用下拉框展开；使用现有边界重投影放大，展示省内采样点。城市详情可定位到该城市附近。该图是天气采样点示意，不是道路地图或景区内部导航图。
- **基础地点按需查询**：初次打开仍只请求 48 个精选目的地；打开一个普通地点时仅请求该地点，展开省份时只补充该省缺失或过期的数据。每批最多 16 个地点，批次串行，避免同时集中请求整个地点库。
- **在线地名搜索**：通过 Open-Meteo / GeoNames 搜索城市、县镇和村落；展示行政归属，选择后先预览天气，可再保存为自己的地点。在线搜索失败时本地检索仍可使用。会取消过期请求，防止旧查询结果覆盖新查询。
- **自定义地点**：支持名称＋WGS84 经纬度，也可在全国/省份/城市附近地图选点后确认。地图选点受投影、源边界和屏幕像素精度影响，是近似位置，需要核对坐标；地图覆盖外的边界、小岛仅在在线地名来源能确认时支持添加。当前开放中国境内，海外时区与底图尚未加入。
- **普通地点不强配图片**：采用中性的坐标地点示意，不编造介绍和实景。保存的地点可作为出发地、查看天气、加入对比、标记去过；已记录足迹的地点需先移回推荐才能移除，避免留下失联足迹。
- **本机地点管理**：最多 100 个自定义地点，支持编辑和移除，名称与注释按文本转义。编辑坐标会清除该地点旧天气，避免错误复用。
- **逐地点缓存时间**：新地点更新不会刷新其他地点的旧时间戳。保留原版足迹与偏好，兼容迁移 v0.2 天气缓存。

## 第二版功能

- **出发地与距离**：从已覆盖的 48 城市中选择出发地，按 200 / 500 / 1,000 / 2,000 km 或不限距离筛选，并可按距离排序。普通和自定义地点可在详情里设为出发地。使用城市中心的 Haversine 近似直线距离，明确标注，不估算交通时间、车票价格或实际道路里程。出发城市自身不进入推荐。
- **日间活动窗口**：可选择 06:00–22:00 内的活动区间，默认 09:00–18:00；仅计算其中的白昼小时，今天已经过去的小时不参与推荐。出发地、距离范围和活动时段会在当前浏览器记住。
- **逐小时推荐**：展示合拍小时、可用白昼小时、最长连续时段和需要留意的情况；普通夜间降雨不会直接抹掉白天的晴好时段。
- **可解释分数**：匹配度改为 0–100 分，在城市详情中展示四项得分依据。分数不表示天气发生概率。
- **目的地比较**：卡片或详情中可选择最多 3 城市，对比天气分数、合拍小时、连续时段、体感、距离和不利条件。变更筛选后保留选择并重新计算，标出不再符合筛选的目的地。
- **小时详情**：每一天展示可点击的小时天气条；点击可查看体感、降水与阵风。全天概况（含夜间）折叠显示。
- **真实数据优先**：失败时使用未过期的真实缓存；无有效缓存则显示暂不可用。演示数据只有主动开启才显示，不会写入真实天气缓存。

## 天气数据与时间口径

使用 Open-Meteo Forecast API，浏览器初次分三批获取 48 个精选城市，随后按省份或单个地点增量查询，时区固定为 `Asia/Shanghai`，单位固定为 °C、mm、cm 和 km/h。每日数据包括天气代码、最低/最高温、降水概率、降水/降雪量、最大风速及阵风；小时数据包括天气代码、气温、体感、降水/降雪量、风速、阵风、云量与是否白昼。

- 小时槽以 `[09:00, 10:00)` 表示；降水/降雪累计量和最大阵风属于前一小时，因此使用 10:00 返回的这些值匹配该槽，其余瞬时条件使用 09:00 值。
- `is_day` 决定是否计入白昼，小时数是小时级估算，不推断分钟精度或精确日照时长。
- 今天的活动小时从下一个完整小时起计算；未来日期按所选活动时段计算。
- 所选日间时段有缺失字段、缺失小时或缺失日期时，该城市不进入推荐，不将空值当作零降水。
- 全部连接失败时不自动展示演示推荐；部分请求成功时只使用有效真实响应，不混合示例数据。

## 推荐口径

默认在有至少一个合拍小时、数据完整、符合距离与温度筛选且没有恶劣天气的城市中排序。

| 偏好 | 小时条件 |
| --- | --- |
| 追阳光 | WMO 0/1/2，云量 ≤ 40%，小时降水 ≤ 0.1 mm，零降雪 |
| 看雪 | WMO 71/73/77/85，小时降雪 > 0 且 ≤ 2 cm |
| 听雨 | 非强降雨的指定代码，小时降水 > 0 且 ≤ 2.5 mm，零降雪，风速 < 25、阵风 < 40 km/h |
| 清凉 | 体感 15–25°C，小时降水 ≤ 0.2 mm，零降雪，风速 < 25、阵风 < 40 km/h |

一天至少一半可用白昼小时合拍，记为一个合拍日。“每天至少半程合拍”要求行程每一天均满足此条件。

评分四项分别四舍五入后相加：

1. 合拍小时：合拍小时 / 可用白昼小时 × 60 分。
2. 连续时段：最长连续合拍时段 / 4 小时 × 15 分，上限 15 分。
3. 体感舒适：小时体感距目标温度越近得分越高，最多 15 分；目标为晴天/听雨 22°C、清凉 20°C、降雪 −3°C。
4. 风速舒适：按日间小时风速计算，最多 10 分。

距离用于单独筛选和排序，不掺入天气分数。地图着色是省内已覆盖城市的平均合拍小时比例，不代表整个省份的天气。无有效采样数据的省份用灰色显示。

所选日期任一天的日级或小时级预报出现冻雾、冻雨、强雨雪、雷暴代码，或日降水 ≥ 50 mm、日降雪 ≥ 15 cm、风速 ≥ 50 km/h、阵风 ≥ 70 km/h，则排除；夜间的这些恶劣天气也会触发排除。当前规则不等同于官方气象预警，不能保证景区或道路安全。降雪预报不代表已有积雪或雪场开放。

## 缓存与足迹

- 真实天气使用紧凑数组格式与每地点独立时间戳存入 `sunseek-weather-v3`，避免逐小时数据占用过多浏览器存储。
- 1 小时内复用缓存；超过 1 小时尝试更新，失败时可保留 6 小时以内的缓存并显示原更新时间；达到 6 小时不再参与推荐。
- 页面定时检查缓存是否到期，重新切回页面时也会检查。
- `v1` 天气缓存不用于小时推荐；`v2` 天气缓存可迁移，`v1` 足迹与 `v2` 旅行偏好继续兼容。
- 自定义地点存入 `sunseek-places-v3`；不包含账号或云端同步。
- 想去清单继续使用 `sunseek-wishlist-v1`；旧的 `sunseek-attractions-v1` 百科资料缓存不再读取或更新。未保存的临时地点不会写入天气缓存。
- 全局时间显示当前数据中最早的获取时间；地点详情与对比表显示每个地点自己的获取时间。
- 演示模式与真实缓存隔离，退出演示会重新获取天气或读取有效真实缓存。
- 足迹和笔记仅存储于当前浏览器。浏览器限制存储时会提示；此时天气仍可在当前页面使用。

地图与行政地点索引来源为阿里云 DataV，澳门陆地轮廓补充自 [Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/)（公有领域）；在线搜索使用 Open-Meteo / GeoNames。Unsplash 图片为意境配图，不表示对应城市的实景。页面采用系统字体回退，不再依赖外部字体请求。

## 测试

需要 Python Playwright 与 Chromium。安装开发依赖后，先启动本地服务，再执行：

```sh
python3 -m pip install playwright
python3 -m playwright install chromium
python3 tests/engine.py
python3 tests/smoke.py
python3 tests/places.py
python3 tests/attractions.py
python3 tests/weather_network.py
```

`tests/engine.py` 检查日间计数、已过去时段、夜雨累计归属、评分分解、距离及缓存边界，不发出网络请求。`tests/smoke.py` 使用确定性天气响应，覆盖四类偏好、出发地/距离、对比、足迹兼容、空值、阵风、日期校验、缓存到期、显式演示和部分请求失败，以及 360 / 390 / 768 / 1024 / 1440px 布局。`tests/places.py` 验证地域去重、同省折叠、省级投影、按需请求、普通地点图片回退、在线查询、坐标校验、自定义地点的持久化/编辑/去重/移除、足迹兼容与注入转义、逐地点时间戳和旧版缓存迁移，以及七个大区的视野、港澳详细轮廓、焦点边界与自动搜索、完整列表地域排序和排序同步、地区搜索与键盘选择。`tests/attractions.py` 检查天气优先布局、城市精选、旧收藏兼容与转义、预览不保存、显式保存与去重、关闭预览后的请求隔离、保存失败回退和手机布局。截图输出到 `/tmp`，不进入 Git。

`tests/weather_network.py` 模拟单批超时后的重试与后续批次、广西缺失/部分/完整预报、吉林限流后手动恢复，并验证只重查缺失地点和手机布局；不消耗真实天气接口配额。
